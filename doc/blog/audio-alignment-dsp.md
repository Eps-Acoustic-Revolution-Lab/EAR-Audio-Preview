# 音频对齐为什么会失败：一个 DSP 算子的设计、测试与消融

> English: [Building an Audio Alignment Operator: Design, Failures, and Ablation](audio-alignment-dsp.en.md)
>
> 2026-10-17 · EAR Audio Preview 研发记录。本文探讨独立研究分支中的整数固定延迟对齐原型（测试环境：Apple M5 Pro / Node.js v24.9.0）。

比较两个音频文件时，我们通常想回答一个具体问题：它们是否只是偏移了几个采样点、存在整体增益差，或者反了极性？把这些差异补偿后，还剩多少真正不同的声音？

互相关（Cross-correlation）能给出一个起点，但仅靠“寻找最大正相关峰”在工程上很容易失效：立体声混音可能导致声道相消，反相信号的正确峰值是负数，周期性信号则会产生多个高度相似的伪峰。此外，在处理长文件时，滤波、数据准备和边界检查的开销往往会反超相关计算本身。

我们以 `audioscope v1.1.8` 为基线实现了自己的对齐算子，并在五轮独立代码审查和一轮完整消融实验后，对各个设计模块的实际收益进行了归因：

- **准确率提升完全来自边界条件处理**：在固定测试语料中，相比基线的正例优势全部归功于**对应声道选择**（解决 Side-only 相消）和**双极性峰值搜索**（解决反相对齐）。
- **多候选搜索的核心价值是拒绝伪解**：引入多候选精修与歧义检查，有效拦截了纯音等周期信号的多解问题。
- **短分析窗口决定了长音频性能**：将粗搜索窗口缩短至 4.5 秒，使 30 秒音频的处理耗时下降了约 71%。
- **频谱部分白化未提升准确率，但间接触发了早退加速**：消融显示白化没有增加正例通过数，但它压低了次峰能量，使部分素材满足提前退出条件，减少了精修计算次数。

## 1. 问题定义与接口设计

**本算子仅解决同采样率下的固定整数延迟与极性估计，并通过最小二乘拟合计算重叠区残差。** 算子不处理变采样率、亚采样延迟、时钟漂移或动态时间规整（DTW）。

设参考信号为 $A$，待比较信号为 $B$，采样率相同。对齐模型定义为：

$$A[n] \approx p\,B[n+d],\qquad p\in\{-1,+1\}$$

其中 $d > 0$ 表示 $B$ 滞后于 $A$，$p$ 表示整体极性，幅度差异由后续的增益拟合处理。原型暴露两个核心接口：

```js
estimateAlignment(aChannels, bChannels, sampleRate, options)
// 返回: { accepted, offsetSamples, polarity, confidence, reason }

compareResidual(aChannels, bChannels, sampleRate, offsetSamples)
// 返回有效重叠区的共享增益、残差 RMS、峰值、相消深度（Null Depth）等

```

`estimateAlignment` 负责判断是否存在可信的整数偏移（`confidence` 为归一化相关系数的绝对值）；`compareResidual` 负责在给定偏移下执行相消测试（Null Test）。

## 2. 对比基线：audioscope v1.1.8

**基线采用“单声道混合 + 4 kHz 粗搜索 + 65,536 点原采样率精修”的粗到细架构，且仅搜索正相关峰。**

为了保证对比可复现，我们将 `audioscope v1.1.8`（commit `0cf17749`）固定在实验目录的 [vendor/](../research/audio-alignment/vendor/) 下。基线的具体流程为：

1. 将多声道平均混合为单声道，去除 DC 偏置。
2. 截取最多前 60 秒音频，通过分块平均降采样至约 4 kHz。
3. 计算普通互相关，选取最大正峰值作为粗略偏移。
4. 回到原采样率，在粗峰邻域内取最多 65,536 个样本进行局部精修，同样寻找最大正值。

我们的算子保留了“去均值 + 粗到细搜索”的主体框架，但在声道准备、分析窗长、降采样滤波、频谱加权和峰值筛选策略上进行了重新设计（代码位于 [operator.mjs](../research/audio-alignment/operator.mjs) 与 [fft.mjs](../research/audio-alignment/fft.mjs)）。

## 3. 预处理与极性：避免在搜索前丢失信号

**通过能量启发式选择单一对应声道对，并以相关系数绝对值评估候选峰，可以直接解决立体声反相相消和整体极性翻转问题。** 这两项改动解释了后续消融实验中相对基线的全部正例准确率优势。

### 3.1 声道选择策略

直接平均左右声道在遇到反相立体声（Side-only）信号时会彻底失效：

$$L=x,\quad R=-x \implies (L+R)/2=0$$

一旦混合为零，后续的延迟估计和增益拟合都会崩溃。我们的做法是不做声道混合，而是挑选一对对应声道进行延迟估计：

1. 对每个声道 $c$，分别计算 $A_c$ 和 $B_c$ 的去均值能量。
2. 以 $\min(\text{Energy}(A_c), \text{Energy}(B_c))$ 作为该声道对的评分。
3. 选择评分最高的声道对进入后续流程，优先保证两侧都有足够强的有效信号。

估计出的整数延迟会统一应用到所有声道。这是一种低成本的能量启发式策略，不涉及多声道联合相关计算。

### 3.2 极性无关的峰值搜索

如果 $B$ 是 $A$ 的反相延迟副本，正确对齐位置的相关系数会接近 $-1$。仅搜索正峰会直接漏掉真实匹配，转而选中旁瓣上的正伪峰。

因此，我们在粗搜索和精修阶段均使用相关系数的绝对值 $\vert{}\rho\vert{}$ 来排序和筛选候选，最后根据最佳匹配的符号确定极性 $p \in \{-1, +1\}$。

## 4. 粗搜索：短分析窗、抗混叠降采样与部分白化

**粗搜索通过缩短分析窗口大幅降低了滤波与 FFT 开销，引入 Blackman-sinc 低通滤波抑制抽取混叠，并尝试用部分白化平衡频谱权重。**

完整处理流程如下：

```text
检查 PCM 有效性 → 选择对应声道对 → 定位高能量区域 → 截取分析窗口
→ FIR 低通与降采样 → 加权互相关 → 提取最多 3 个粗峰 → 原采样率精修 → 阈值与歧义判定

```

### 4.1 分离搜索范围与分析窗口长度

允许默认 $\pm 2$ 秒的延迟搜索范围（$T_{\text{lag}}$），并不需要把整段 30 秒或 60 秒的音频全部送入 FFT。我们在前 60 秒的共同长度内定位高能量区域，仅截取一段短窗口进行分析：

$$T_{\text{window}}=\max(4,\;2T_{\text{lag}}+0.5)\ \text{秒}$$

默认配置下，分析窗口为 4.5 秒。随后以 $\lfloor f_s / 2000 \rfloor$ 的抽取因子降采样至约 2 kHz。

以 48 kHz、30 秒的音频为例：基线需要处理约 120,000 个粗采样点（对应 262,144 点 FFT）；而 4.5 秒短窗口每路仅有 9,000 点，FFT 长度缩减至 32,768 点，大幅降低了长音频的预处理和频域变换成本。

### 4.2 降采样前的抗混叠滤波

基线在降采样时使用的是简单的分块平均（矩形窗）。我们改用了 Blackman 窗 sinc FIR 低通滤波器：滤波器半径设为抽取因子的 4 倍，截止频率设为目标 Nyquist 频率的 80%，并对滤波核做归一化。虽然高阶 FIR 的单点计算成本更高，但配合 4.5 秒的短窗口，整体耗时依然可控。

### 4.3 频谱部分白化（Partial Whitening）

设 $A$、$B$ 的频谱分别为 $X$、$Y$，交叉频谱为 $S_k = \overline{X_k}Y_k$。普通互相关直接对 $S_k$ 做逆 FFT，容易被能量集中的低频成分主导；而完整的广义互相关相位变换（GCC-PHAT）只保留相位，又容易放大静音频段的本底噪声。

我们在粗搜索中采用了介于两者之间的部分白化权重：

$$C=\operatorname{IFFT}\!\left( \frac{S_k}{\sqrt{\max(\epsilon,\vert{}S_k\vert{})}} \right),\qquad \epsilon=\max\left(10^{-20},\;10^{-5}\max_k \vert{}X_k\vert{}\vert{}Y_k\vert{}\right)$$

设计初衷是削弱强频段的垄断，让更多频段参与时间定位。不过后文的消融实验表明，在当前测试集上，它的实际作用体现在计算性能而非准确率上。

## 5. 精修与拒绝策略：处理周期信号的多解歧义

**高相关系数不代表偏移唯一。通过保留多个粗峰候选、单遍统计精修以及跨候选歧义检查，算子能够有效识别并拒绝周期信号的多解问题。**

### 5.1 原始矩单遍精修

粗搜索按幅值选出最多 3 个局部峰值。对每个候选峰，回到原采样率，在其左右各 2 倍抽取因子的邻域内进行逐样本搜索。

精修窗口最多取 16,384 个样本。当有效重叠不足 128 点或信号方差过低时，直接返回 0。为了减少内存遍历，我们不采用“先算均值、再算中心化乘积”的两遍做法，而是在一次遍历中同时累加 $\sum A$、$\sum B$、$\sum A^2$、$\sum B^2$ 和 $\sum AB$，通过原始矩公式直接计算去均值归一化相关系数：

$$\rho(d)= \frac{\sum ab-\frac{\sum a\sum b}{N}} {\sqrt{\left(\sum a^2-\frac{(\sum a)^2}{N}\right) \left(\sum b^2-\frac{(\sum b)^2}{N}\right)}}$$

### 5.2 接受阈值、歧义拒绝与提前退出

精修完成后，候选结果需通过两道门禁：

1. **置信度阈值**：最佳候选的相关系数需满足 $\vert{}\rho_{\text{best}}\vert{} \ge 0.75$。
2. **歧义检查（Ambiguity Check）**：若存在另一个不同偏移的候选峰，其得分满足 $\vert{}\rho_{\text{other}}\vert{} > 0.985 \times \vert{}\rho_{\text{best}}\vert{}$，则拒绝对齐并标记为 `ambiguous-peaks`。

这主要是为了拦截正弦波等周期信号——纯音每隔一个周期就会产生一个接近 1.0 的相关峰，此时给出任意单一延迟都是武断的。

此外，为了减少不必要的精修开销，我们加入了提前退出（Early Exit）启发式规则：如果第一个粗峰精修后的 $\vert{}\rho\vert{} > 0.999$，且第二个粗峰的粗略幅值不到第一峰的一半，则直接采纳第一候选，跳过剩余候选的精修。

## 6. 测试语料构建与基准验证

**测试语料覆盖了合成边界条件、共享调性的负例干扰以及真实音频变换，最终确立了 0.75 的相关接受阈值，并在留出集上达到 100% 通过率。**

测试生成器位于 [corpus.mjs](../research/audio-alignment/corpus.mjs)。基础信号由带包络的滤波噪声、扫频正弦和定频正弦混合而成。

* **正例集**：覆盖正负整数延迟、搜索范围边界、增益缩放、DC 偏置、加性噪声、整体反相、Side-only 立体声、左右声道能量失衡、前导静音以及一阶低通滤波（低通会改变群延迟与波形包络，容差放宽至 2 samples，其余正例严格要求误差在 1 sample 以内）。
* **负例集**：包含静音、常量信号、纯音周期信号，以及“不同随机噪声但共享相同调性结构/包络”的合成信号。

在早期开发测试中（见 [dev-round-1.json](../research/audio-alignment/results/dev-round-1.json)），有 **5/24 个共享调性结构的负例被误接受**，其相关系数分布在 `0.49–0.52` 之间。这说明具有相似频谱包络的独立音频很容易产生中等强度的互相关。据此，我们将最终接受阈值上调至 `0.75`。

阈值固定后，在 104 例验证集（72 正例 + 32 负例）和 16 例真实音频变体（4 首 48 kHz 立体声音乐，施加延迟、增益、噪声与反相）上的表现如下：

| 测试集 | 原型算子 | audioscope v1.1.8 | 差异原因 |
| --- | --- | --- | --- |
| 合成正例 (72) | **72 / 72** | 56 / 72 | 基线在反相与 Side-only 案例上失败 |
| 合成负例 (32) | **32 / 32 拒绝** | 无拒绝机制 | 原型有效拦截静音、不相关信号与周期多解 |
| 真实素材变体 (16) | **16 / 16** | 12 / 16 | 基线在 4 个反相变体上失败 |

## 7. 增益拟合与残差计算

**对齐后的残差评估采用全声道联合最小二乘拟合共享增益，仅在有效重叠区内计算，且允许负增益以兼容反相相消。**

确定偏移量 $d$ 后，`compareResidual` 在有效重叠区域 $\Omega$ 内，跨所有声道拟合一个统一的标量增益 $g^*$：

$$g^*=\frac{\sum_{c,n\in\Omega} A_{c,n}B_{c,n+d}} {\sum_{c,n\in\Omega} B_{c,n+d}^{2}}, \qquad e_{c,n}=A_{c,n}-g^*B_{c,n+d}$$

相消深度（Null Depth）定义为参考信号能量与残差能量之比的分贝值：

$$\text{Null Depth (dB)} = 10\log_{10}\!\left(\frac{\sum A_{c,n}^2}{\sum e_{c,n}^2}\right)$$

相比基线 `fitGain` 仅支持单声道且强制要求正增益的设计，全声道共享增益保留了立体声平衡，排除了首尾未对齐区域的补零干扰，更符合音频工程中 Null Test 的物理意义。

## 8. 性能演进轨迹

**算子在初版中因高阶 FIR 和全量检查比基线慢约 40%；通过引入短分析窗、提前退出和循环展开，最终在 30 秒长音频上达到基线 2.8 倍以上的速度。**

我们定义加速比为 `基线耗时 / 原型耗时`（大于 1 表示原型更快）。四个迭代阶段的性能变化如下（数据见 [历史计时](https://github.com/Eps-Acoustic-Revolution-Lab/EAR-Audio-Preview/tree/4f0a2361c10f89a881d52d118b43761cbd1840a7/doc/research/audio-alignment/.cross-gan/baseline/) 至 [最终验证](../research/audio-alignment/results/final-verification.json)）：

1. **第一版（30s: ~0.63x | 3s: ~0.58x）**：修复了声道与极性缺陷，但由于使用高阶 Blackman-sinc FIR 处理全长信号，整体速度比基线慢。
2. **第二版（30s: ~1.03x | 3s: ~0.75x）**：优化了 PCM 合法性检查，并加入精修提前退出机制，长音频耗时追平基线。
3. **第三版（30s: ~1.80x | 3s: ~0.95x）**：将粗搜索窗口缩短至 4.5 秒，并简化了 FIR 滤波器的边界分支循环，长音频性能大幅反超。
4. **最终版（30s: 2.80x–2.87x | 3s: 1.33x–1.38x）**：经过五轮代码审查与循环展开优化后，长短音频均稳定快于基线。

## 9. 五轮对抗审查：边界缺陷与热点优化

**通过“独立构造反例 + 独立修复验证”的五轮审查，我们修复了稀疏信号漏检、窗口步进盲区、底噪干扰等 4 个边界 Bug，并通过循环展开降低了约 25% 的长音频检查开销。**（完整记录见 [审查记录](https://github.com/Eps-Acoustic-Revolution-Lab/EAR-Audio-Preview/tree/4f0a2361c10f89a881d52d118b43761cbd1840a7/doc/research/audio-alignment/.cross-gan/checkpoint.json)）

### 第 1 轮：跨步采样探针漏检周期性稀疏信号

为了加速静音检测，初版代码每隔 32 个采样点抽取一个值计算能量。如果输入信号恰好只在 `i % 32 === 1` 的位置有非零脉冲，探针读取到的全为 0，导致两段完全一致的有效音频被误判为静音：

```js
import { estimateAlignment } from './doc/research/audio-alignment/operator.mjs';

const x = new Float32Array(48000);
let state = 7;
for (let i = 1; i < x.length; i += 32) {
  state = (Math.imul(state, 1664525) + 1013904223) >>> 0;
  x[i] = state / 4294967296 - 0.5;
}
console.log(estimateAlignment([x], [x.slice()], 48000)); // 初版误报为静音

```

**修复**：保留 32 点快速探针作为快速路径；当探针判定能量不足时，不直接拒绝，而是回退到全样本扫描确认。

### 第 2 轮：窗口选择器的跨步探针将分析窗定在静音区

修复声道静音检测后，如果把上述稀疏脉冲移到 1 秒音频的后半段，声道级回退能通过，但负责挑选分析窗口的函数使用了步长为 16 的能量探针，同样会漏掉后半段的稀疏信号，最终把精修窗口定在前半段的静音区。

**修复**：为分析窗口选择器也补齐了低能量下的全样本扫描回退。

### 第 3 轮：固定半窗步进遗漏音频尾部

窗口选择器以半个窗长（`hop = windowSize / 2`）滑动。对于 48,000 点的输入和 16,384 点的窗口，起点依次为 `0, 8192, 16384, 24576`，最后一个窗口仅覆盖到 `40960`。如果有效瞬态信号恰好出现在 `46000` 之后，所有候选窗口都无法捕获。

**修复**：当常规滑动窗口能量不足时，显式追加一个与输入末端对齐的窗口（`[length - windowSize, length]`）参与评估。

### 第 4 轮：展开全量 PCM 有限值检查循环

每次调用算子前，都会遍历全部采样点检查是否存在 `NaN` 或 `±Infinity`。在长音频上，这个简单循环占据了可观的耗时。

**修复**：将标量循环改为每次迭代顺序检查 8 个样本的展开形式（尾部余数仍走标量循环），不跳过任何元素。实测显示，该改动使 30 秒音频的算子总耗时直接下降了 **25%–27%**，3 秒音频下降 **6%–7%**。

### 第 5 轮：极弱本底噪声绕过严格的零能量回退条件

第 2、3 轮的全样本回退最初仅在粗探针能量严格等于 `0` 时触发。如果音频前段不是纯零，而是混有幅度极小（如 `1e-9`）的本底噪声，探针能量大于零，就会直接选中前段底噪区，错失尾部的有效信号。

**修复**：将触发完整回退的阈值从 `=== 0` 放宽至 `< 1e-12`（与声道静音阈值对齐），确保极弱底噪下也能正确回退并扫描尾部窗口。

## 10. 两个被回退的“负优化”

**理论计算量更少或微基准测试更快，不等于在 V8 JIT 中运行的完整算子更快。** 我们在实验中回退了两个看似合理的优化：

1. **合并双路正向 FFT**：$A$ 和 $B$ 的长度相同，理论上可以在单次循环中同步完成两路信号的位反转排列与蝶形运算，共享旋转因子递推。局部测试虽有微弱提升，但在完整算子计时中，8 组测试的中位加速比仅为 `1.006x`，部分场景反而变慢，遂回退。
2. **融合双路 FIR 降采样循环**：尝试在同一个循环内使用同一组 FIR 系数同时卷积累加 $A$、$B$ 两路信号。独立内存基准测试表现良好，但合入生产文件后，V8 的优化行为发生变化：短音频速度跌至原来的 `0.84x–0.88x`，长音频跌至 `0.95x–0.96x`。

这两次尝试表明，在 JavaScript 数值计算中，手动合并循环可能会破坏引擎自动向量化或寄存器分配策略，一切优化必须以端到端实测计时为准。

## 11. 消融实验：拆解各组件的真实贡献

**消融实验表明：正例准确率的提升完全由“声道选择”和“极性支持”贡献；多候选机制负责拦截周期伪解；而耗时的大幅下降主要归功于“短分析窗”。**

为了避免把所有改动打包成糊涂账，我们将算子冻结，对**声道选择、部分白化、多候选精修、短分析窗**四个模块做全因子消融（$2^4 = 16$ 组配置），外加“关闭极性支持”和“audioscope 基线”，共测试 18 个版本。测试集扩充至 **318 例（230 正例 + 88 负例）**。

### 11.1 准确率归因

| 实验配置 | 正例通过 (230) | 负例拒绝 (88) | 失败案例归因 |
| --- | --- | --- | --- |
| **完整算子 (Full)** | **230 / 230** | **88 / 88** | 无 |
| 关闭声道选择 | 204 / 230 | 88 / 88 | 漏掉全部 26 例 Side-only 声道相消样本 |
| 关闭极性支持 | 204 / 230 | 88 / 88 | 漏掉 22 例合成反相 + 4 例真实素材反相样本 |
| 关闭多候选精修 | 230 / 230 | **66 / 88** | 22 例纯音周期多解负例无法触发歧义拒绝，被误接受 |
| 关闭部分白化 | 230 / 230 | 88 / 88 | 对当前语料的通过率无影响 |
| 关闭短窗口 (用全长) | 230 / 230 | 88 / 88 | 对当前语料的通过率无影响 |
| **audioscope 基线** | **178 / 230** | N/A | 失败的 52 例恰好是“26 例声道相消 + 26 例反相”的无交集并集 |

可以看到，除这 52 个特殊边界案例外，其余 178 个常规正例上双方表现完全一致。多候选机制的价值也得到了明确界定：它与跨候选歧义检查绑定，专门用于拦截周期性信号的非唯一解。

### 11.2 耗时归因

使用 4 首真实音频的 3 秒和 30 秒版本进行穿插轮转基准测试（共 3,024 次正式调用）。定义指标为 `关闭该模块后的耗时 / 完整算子耗时`（比值越大，说明该模块带来的提速越明显）：

* **短分析窗口**：3 秒输入下比值为 `0.998x`（因为短窗口本身就是 4.5 秒，对 3 秒音频无截断效果）；**30 秒输入下比值高达 `3.472x**`，耗时从 37.0 ms 直接降至 10.6 ms（节省约 71%）。
* **声道选择**：3 秒为 `1.332x`，30 秒为 `1.447x`。启用声道选择后耗时减少 25%–31%，这主要因为省去了全长立体声混合的新数组分配与遍历开销。
* **多候选精修**：3 秒为 `1.005x`，30 秒为 `0.997x`，耗时波动在 $\pm 2\%$ 以内。
* **部分白化**：表现出强素材依赖性。关闭白化后，3 秒的素材 A/C/D 变慢了约 35%，但素材 B 快了 8%；30 秒的素材 A 变慢了 12%，而素材 B/C/D 快了约 9%。

## 12. 性能追因：为什么去掉频谱白化反而可能变慢？

**部分白化本身会增加频域计算开销，但它锐化了主相关峰并压低了次峰，使多数素材得以在第 1 个候选峰后直接触发提前退出，省去了后续 2 个候选峰的时域精修。**

从直觉上看，关闭频谱白化少了一步复数模长开方与除法，速度应该更快才对。为了解释上一节中“关闭白化反而变慢”的现象，我们在不干扰计时的前提下，对算子内部的实际工作量进行了插桩计数（见 [工作量计数](../research/audio-alignment/ablation/work-counts.mjs)）：

1. **短窗口的工作量差异**：在 30 秒音频上，使用 4.5 秒短窗时，FFT 长度为 32,768，双路 FIR 滤波共执行约 347 万次乘加运算；若关闭短窗處理全长，FFT 膨胀至 131,072 点，FIR 乘加暴增至 2,316 万次。
2. **白化对精修次数的影响**：在启用白化的完整配置下，全部 8 组真实音频在精修完第 1 个粗峰后，均满足 $\vert{}\rho_1\vert{} > 0.999$ 且第二粗峰低于第一峰一半的早退条件，因此总共只执行了 **97 次**时域相关精修。而关闭白化后，普通互相关的次峰能量较高，导致 3 秒的 A/C/D 和 30 秒的 A 无法触发早退，被迫跑满全部 3 个候选峰的邻域搜索，精修调用次数飙升至 **291 次**。这恰好对应了计时实验中变慢的那几组素材。

为了进一步证实这一交互效应，我们补充了一组将候选数强制锁死为 1（即消除早退机制差异）的对照实验。结果显示：**当固定为单候选时，关闭白化在所有 8 组测试上无一例外都更快（耗时减少 6%–13%）**。这完整闭环了性能归因：白化的净收益取决于“它所节省的时域精修开销”是否大于“它自身的频域计算成本”。

## 13. 复现指南与代码索引

本项目零外部 npm 依赖，需使用 Node.js 24+ 运行。

### 复现步骤

从仓库根目录进入下面的研究快照后，可直接运行合成语料测试。冻结的消融验证需要原始 PCM 及其哈希；替换素材只能用于重新实验，不能验证原始计时结果。真实音频计时需准备 4 份本地音频（`A.mp3`–`D.mp3`），通过脚本转换为标准测试 PCM：

```sh
cd doc/research/audio-alignment

# 1. 准备本地音频并运行基础测试与评估
node prepare-audio.mjs /path/to/audio-directory
npm test
npm run evaluate

# 2. 运行双轮性能基准测试与校验
node --expose-gc timing.mjs
cp results/timing.json results/timing-pass-1.json
node --expose-gc timing.mjs
npm run verify

# 3. 运行完整消融实验与工作量计数分析
node ablation/run.mjs accuracy > ablation/accuracy.log
node --expose-gc ablation/run.mjs bench > ablation/timing.log
node ablation/work-counts.mjs
node --expose-gc ablation/interaction.mjs > ablation/interaction.log
node ablation/run.mjs report > ablation/report.log

```
